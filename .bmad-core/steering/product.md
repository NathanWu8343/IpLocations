## 產品目的
IpLocations.Api 是一個供內部與合作系統存取的 REST API，提供 IPv4 位址對應的國家/地區資訊。藉由查詢 Redis 中預載的 IP 範圍資料，協助上游服務在決策、合規或地域化體驗中快速判斷使用者來源地。

## 目標使用者
- **內部產品團隊**：需要在業務流程中進行地理位置控管或統計的後端服務。
- **基礎設施/平台團隊**：整合中心化 IP 判斷能力，降低各系統自行維護 IP 資料的成本。
- **合作夥伴服務**：透過 API Gateway 或內部網路取得地區資訊，用於分流、定價或合規檢查。

## 主要功能
1. **IPv4 位置查詢 API**：`GET /api/IpLocations?ip=` 回傳 ISO Alpha-2 國碼或 404。
2. **Redis 範圍查詢**：透過 `SortedSetRangeByScoreAsync` 取得最相近區段，驗證 IP 是否落在定義範圍內。
3. **啟動時預載資料**：`IpRangeStore.WarmUp()` 於應用程式啟動時載入初始範例資料，確保服務可立即回應。

## 商業目標
- 提供穩定、可擴充的 IP-to-country 能力，減少重複建置成本。
- 降低查詢延遲，支援即時決策與個人化體驗需求。
- 透過 API 封裝與版本化，為未來擴充（如 IPv6、更多資料來源）奠定基礎。

## 成功指標
- **準確率**：IPv4 對應正確率 ≥ 99%。
- **延遲**：P95 API 回應時間 ≤ 30 ms（內網環境）。
- **可用性**：月度 API 成功率 ≥ 99.9%。

## 產品原則
1. **資料可信度優先**：確保匯入的 IP 範圍資料來源可靠並具備更新流程。
2. **低延遲回應**：所有查詢需保持記憶體與快取導向的查詢模式，避免阻塞式操作。
3. **可演進性**：設計需支持未來擴充（IPv6、外部資料載入、自動化 warm-up）。

## 監控與可見性 (如適用)
- **儀表板類型**：目前依賴 ASP.NET Core 內建記錄與基礎監控；建議整合至集中式 APM（如 Application Insights 或 Prometheus）進行可視化。
- **即時更新**：透過伺服器指標與 Redis 監控（INFO、慢查詢）追蹤效能。
- **顯示的關鍵指標**：API 成功率、查詢延遲、Redis 命中率、Warm-up 成功狀態。
- **共享功能**：未提供專屬儀表板，共享以現有監控平台的唯讀權限為主。

## 未來願景
### 潛在增強功能
- **資料載入自動化**：建立定期批次或串流機制，從官方或商業資料來源匯入最新 IP 範圍。
- **IPv6 支援**：調整資料結構與查詢流程以涵蓋 IPv6。
- **多區域部署**：針對跨資料中心或雲端多區域擴散，優化 warm-up 與同步策略。
- **合規與稽核**：提供查詢紀錄追蹤與分析工具，支援審計需求。
