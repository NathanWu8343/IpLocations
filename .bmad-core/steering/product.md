# 產品總覽

## 產品目的
IpLocations API 旨在提供**快速、可信且易於整合的 IP 地理位置查詢服務**，協助應用程式在毫秒級時間內判定使用者來源國家，支援地區化內容、法規遵循與安全風控決策。

## 目標使用者
- **雲端與平台團隊開發者**：需要在既有服務中嵌入 IP-to-country 判定以進行內容分流或價格區隔。
- **資安與風控工程師**：需要以低延遲方式辨識可疑流量來源，快速建立封鎖或通過規則。
- **營運分析人員**：需要可信的 IP 地緣資料，協助追蹤市場成長與使用者分布。

## 主要功能
1. **單點 IP 查詢**：提供 RESTful `GET /ip-locations/{ip}` 端點，輸入 IPv4 位址即可取得對應的 ISO 3166-1 alpha-2 國家代碼。
2. **高效能資料尋址**：透過 Redis Sorted Set 儲存 IP 區段，使用 score 範圍查詢在記憶體中完成 O(log n) 檢索，P99 延遲目標小於 100 毫秒。
3. **開發者自助整合**：啟用 Swagger UI 與 JSON OpenAPI 規格，提供互動式測試與 SDK 產生器支援；同時公開 `IpConverter` 工具協助資料前處理。

## 商業目標
- **降低導入成本**：讓內部專案得以共用同一套 IP 查詢服務，避免重複購置第三方授權或維護多套資料庫。
- **提升服務可靠度**：透過快取化查詢與高可用架構，把關使用者登入、串流與交易流程的地區判斷。
- **創造延伸價值**：為後續付費層級（例如更精細的地區或 ISP 資料）奠定技術基礎與使用量。

## 成功指標
- **效能**：P99 API 延遲 < 100 ms；單機每秒查詢數 (RPS) 穩定於 2,000 以上。
- **穩定性**：全年可用性 ≥ 99.9%，Redis 連線中斷自動恢復時間 < 30 秒。
- **採用率**：首年內至少 3 個核心產品整合，月度查詢量季成長率 ≥ 15%。

## 產品原則
1. **效能優先**：所有產品決策均以維持低延遲、高吞吐為首要考量，避免引入阻塞式流程。
2. **輸入可信**：提供清晰錯誤回傳與邊界檢查，確保整合方能快速定位問題並回報。
3. **資料新鮮**：維持 IP 區段資料更新流程，確保對應結果與最新全球地緣資訊一致。

## 監控與可見性 (如適用)
- **儀表板類型**：建議透過雲端監控（例如 Azure Dashboard、Grafana）集中呈現。
- **即時更新**：整合 Application Insights 或 Prometheus 指標，以 1 分鐘為週期蒐集查詢量與延遲。
- **顯示的關鍵指標**：請求數量、P95/P99 延遲、Redis 連線狀態、查詢命中率。
- **共享功能**：提供唯讀儀表板連結與日誌匯出，供營運或資安團隊週期檢視。

## 未來願景

### 潛在增強功能
- **IPv6 支援**：延伸現有資料模型以處理 IPv6 區段與 CIDR。
- **地區細緻度**：加入州、省、城市或 ISP 層級資訊，支援更細緻的內容調整。
- **協作功能**：提供角色權限與事件通知，讓營運與資安團隊能即時共享查詢洞察。
