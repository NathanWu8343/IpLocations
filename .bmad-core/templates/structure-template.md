# Project Structure

## Purpose
定義專案的目錄與檔案結構、命名慣例、匯入模式及程式碼組織原則，以促進一致性、可維護性與可擴展性。

## Core Principles
- **清晰性**: 目錄與檔案結構應直觀易懂。
- **一致性**: 在整個專案中保持命名與組織慣例的一致性。
- **模組化**: 將相關功能分組以促進可維護性。
- **分離關注點**: 不同功能區域應清晰分離。
- **可測試性**: 結構應促進單元測試與整合測試。
- **依賴管理**: 清晰定義模組之間的依賴關係。
- **文件化**: 結構與慣例應有良好文件說明。

3. **可測試性**: 建構易於測試的程式碼
4. **一致性**: 遵循程式碼庫中已建立的模式

### 關注點分離
- 儀表板與核心業務邏輯隔離
- 自有 CLI 進入點以獨立運作
- 對主應用程式的依賴最小化
- 可在不影響核心功能的情況下停用
