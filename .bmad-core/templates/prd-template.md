
# Specification Template

## Guidelines

### 指導原則
- **聚焦使用者價值**：清晰定義使用者**需要什麼 (What)** 以及**為什麼需要 (Why)**
- **嚴守技術中立**：絕不描述**如何實作 (How)**，禁止包含 API、框架或程式碼等細節
- **面向業務溝通**：確保內容對非技術背景的利害關係人易於理解
- **合理推測**：使用情境、行業標準和常見模式來填補空白

## Process Flow

### 1. 載入指導文件
讀取並提取關鍵資訊：
- `.bmad-core/steering/product.md` → 產品目標、使用者需求

### 2. 情境分析與需求拆解

**推論與分析流程（內部思考）：**

a. 基於傳入的 `<feature-name>` 與 `<description>` 
   分析功能描述，提取核心需求與關鍵資訊
   識別功能範圍、使用者角色、預期效益  
b. 結合功能描述與 `product.md`，進一步拆解並細化使用者情境
c. 引用資訊時請標記來源 `[來源：product.md#章節名稱]`
d. 對於不清楚的方面：
    - 請依據情境及業界標準合理推測
    - 僅在以下情況下標記 `[NEEDS CLARIFICATION: 具體問題]`：
      * 功能範圍與邊界（包含/排除哪些使用案例）
      * 使用者類型與權限（若有多種解釋可能）
      * 數量級或效能要求（「大量」是多少？「快速」是幾秒？）
      * 安全性或合規性需求（涉及法律/財務時）

### 3. 填寫範本內容

請依照下方 Template 結構，逐步、完整填寫每個章節內容：
- 所有描述必須清楚、具體且可驗證
- 嚴禁加入任何實作細節或技術方案

**如內容含 `[NEEDS CLARIFICATION]` 標記時：**
- 請於文件指定佔位符新增「## 待補充資訊」章節
- 以條列方式列出所有需澄清問題，格式如下：
  - `[問題描述]（章節：[章節名稱]）`
- 每個問題需明確標註所屬章節，便於後續追蹤

請確保每個章節內容均符合上述要求，並維持結構一致性。
