# Requirements Template

## 執行流程

### 1. 分析功能需求
- 取得 `<feature-name>` 與 `<description>` 參數
- 分析功能描述，提取核心需求與關鍵資訊
- 識別功能範圍、使用者角色、預期效益

### 2. 檢視程式碼庫
- 使用 `think` tool 規劃分析策略：
  * 根據功能名稱與描述，擬定搜尋關鍵字
  * 確認核心業務邏輯目錄作為搜尋範圍
  * 設定可重用性判斷標準（如功能相似、介面相容）
- 搜尋並識別可重用元件（如資料模型、服務、工具類）
- 尋找新功能的整合點
- 記錄可重用部分與需新建部分

### 3. 載入指導文件
讀取並提取關鍵資訊:
- **product.md** → 產品目標、使用者需求
- **tech.md** → 技術標準、最佳實踐
- **structure.md** → 檔案結構、命名慣例
- **architecture.md** → 架構模式、整合方式

### 4. 填寫樣板
按照「樣板」區段填寫完整需求文件

### 5. 品質驗證
執行「品質檢查清單」確保文件完整性

---

## 快速指南

### EARS 格式速查
1. **普遍性**: `[系統] 應 [動作]`
2. **事件驅動**: `當 [事件] 發生時，則 [系統] 應 [回應]`
3. **狀態驅動**: `在 [狀態] 期間，[系統] 應 [行為]`
4. **非預期行為**: `如果 [異常] 發生，則 [系統] 應 [處理]`
5. **可選功能**: `在 [條件] 下，[系統] 應能夠 [行為]`

**原則**: 避免模糊詞彙、確保可測試、優先使用事件驅動與非預期行為模式

### 來源標註規則
- **格式**: `來源:檔案名稱#章節名稱`
- **範例**: `來源:product.md#核心目標`

## 品質檢查清單

- [ ] 所有區段已完成 (無 `[待填寫]` 等預留位置)
- [ ] 每個使用者故事都有 3-5 個驗收標準
- [ ] 所有驗收標準符合 EARS 格式
- [ ] 可重用元件已標註檔案路徑
- [ ] 所有引用已標註來源
- [ ] 技術選型明確 (資料庫、快取、框架)
- [ ] 效能指標具體 (有明確數值)
- [ ] 成功標準可量化

```markdown

[功能概觀:描述此功能的核心內容、主要使用情境與目標使用者]

[描述要解決的問題，應包含:

_本章節內容由程式碼庫分析識別_

### Existing Components

- **[元件名稱]**: [用途說明與整合方式] _(來源:[檔案路徑])_

### Integration Points
[說明新功能將與現有系統連接的位置]
- **[整合點名稱]**: [整合方式、介面說明與資料流向]

### New Components Required
[列出需要從頭建立的元件]
- **[元件名稱]**: [為何需要新建、預期功能與技術選型考量]

## Requirements

### Requirement 1

**User Story:** 身為 [角色]，我想要 [功能]，以便 [效益]

**Acceptance Criteria**

_驗收標準採用 EARS 格式 (詳見「快速指南」)_

## Non-Functional Requirements

### Performance
[效能需求:包含回應時間、吞吐量、並發處理能力等具體指標]

### Security
[安全性需求:包含驗證、授權、資料加密、隱私保護等要求]

### Reliability
[可靠性需求:包含可用性目標、錯誤處理、災難復原等規範]

### Usability
[可用性需求:包含介面易用性、無障礙設計、學習曲線等標準]

_業務層級的成效指標，與 Acceptance Criteria (功能層級驗證) 不同_

- [可衡量的業務成果:例如使用者採用率、轉換率、滿意度]
- [關鍵績效指標 (KPI):具體數值目標與衡量方式]
- [成功門檻:定義最低可接受的成效標準]

## Definition of Done (DoD)

- [ ] 所有需求均已實作並通過驗收標準
- [ ] 相關文件已更新且完整
- [ ] 程式碼已通過測試 (單元測試、整合測試、回歸測試)
- [ ] 無重大缺陷或阻礙問題
- [ ] 已完成程式碼審查並獲得批准
- [ ] 部署流程已驗證且可順利執行
- [ ] 使用者手冊或操作指引已提供 (如適用)
- [ ] 非功能性需求已驗證達標

- 技術限制
- 時間軸限制
- 資源限制

- **內部相依性**:[其他團隊交付物、共用元件、基礎設施]
- **順序相依性**:[必須先完成的前置功能或任務]

## Out of Scope

- 明確排除的功能或需求
- 不在本次開發範圍內的技術或平台
- 非目標使用者群的相關需求
- 未來版本才考慮的擴充或整合
- 其他不屬於本專案目標的事項
```
