
# 需求規格：API 點擊統計

## 1. 簡介

### 1.1. 目的

本文件旨在定義「API 點擊統計」功能的需求。此功能將追蹤每個國家代碼（Country Code）被查詢的次數，並提供一個 API 端點以查詢這些統計數據。

### 1.2. 範圍

-   **IN**:
    -   新增一個 API 端點，用於記錄 IP 地區查詢的點擊次數。
    -   新增一個 API 端點，用於獲取依點擊次數排序的國家代碼統計數據。
    -   統計數據需儲存於 Redis 中。
-   **OUT**:
    -   使用者身份驗證或授權。
    -   詳細的日誌記錄系統。
    -   歷史數據的長期存檔。

### 1.3. 與產品願景的對齊

此功能透過提供有價值的數據洞察，豐富了產品的核心功能，符合「提供高效能、可擴展的 IP 地區查詢服務」的產品願景。

## 2. 使用者故事與驗收標準

### 2.1. 記錄 API 查詢點擊 (ID: US-001)

**身為** 系統，
**我想要** 在每次成功的 IP 地區查詢後，自動為對應的國家代碼增加一次點擊計數，
**以便** 能夠追蹤不同國家的查詢熱度。

| 驗收標準 ID | 描述                                                                                                                            |
| :---------- | :------------------------------------------------------------------------------------------------------------------------------ |
| AC-001.1    | **WHEN** `IpLocationsController` 的 `Get` 方法成功回傳一個國家代碼時，<br/>**THEN** 系統應異步地將該國家代碼的計數加一。             |
| AC-001.2    | **WHEN** `IpLocationsController` 的 `Get` 方法因 IP 無效或找不到對應地區而回傳 `NotFound` 時，<br/>**THEN** 系統不應記錄任何點擊。 |
| AC-001.3    | **IF** 該國家代碼是第一次被查詢，<br/>**THEN** 系統應在 Redis 中為其建立一個新的計數器，並將其值設為 1。                           |

### 2.2. 查詢點擊統計 (ID: US-002)

**身為** 數據分析師，
**我想要** 透過一個 API 端點獲取所有國家代碼的點擊次數統計，並按點擊次數由高到低排序，
**以便** 能夠快速識別最常被查詢的國家。

| 驗收標準 ID | 描述                                                                                                                            |
| :---------- | :------------------------------------------------------------------------------------------------------------------------------ |
| AC-002.1    | **WHEN** 向 `GET /api/statistics` 發出請求時，<br/>**THEN** 系統應回傳一個 JSON 陣列，其中包含所有國家代碼及其對應的點擊次數。     |
| AC-002.2    | **GIVEN** 系統中有 `{"TW": 100, "CN": 80, "CA": 120}` 的點擊數據，<br/>**WHEN** 請求統計 API 時，<br/>**THEN** 回應的陣列應按 `CA`, `TW`, `CN` 的順序排序。 |
| AC-002.3    | **IF** 系統中沒有任何點擊數據，<br/>**THEN** 統計 API 應回傳一個空的 JSON 陣列。                                                   |

## 3. 非功能性需求

| 需求 ID | 類別 | 需求描述                                                               |
| :------ | :--- | :--------------------------------------------------------------------- |
| NFR-001 | 效能 | 記錄點擊的操作不應顯著增加原 `/api/ip-locations` 端點的回應時間。        |
| NFR-002 | 效能 | `GET /api/statistics` 端點在 1000 個國家數據的情況下，應在 200ms 內回應。 |
| NFR-003 | 可靠性 | 統計數據應持久化儲存在 Redis 中，確保應用程式重啟後數據不會遺失。      |

## 4. 限制與假設

-   **限制**:
    -   所有統計數據將儲存在單一的 Redis 實例中。
    -   不考慮分散式計數的原子性問題，暫時接受非絕對精確的計數。
-   **假設**:
    -   Redis 服務是可用且穩定的。
    -   國家代碼（例如 "TW", "CN"）的格式是固定的，且與 `IpRangeStore` 中使用的代碼一致。
